## プロジェクトの最終目標

SteamVR HMDを装着し、Blender内の楽しい世界をサイクルトレーナーで走行・飛行できるGPL-3.0-or-laterのBlender Extensionを作る。ArriettyはVersion 0.8.0の空で機能完了とする。Google由来の世界はArrietty完了後に、別のBlenderプラグイン「Secret World」として開発する。

実装順序は機能を分離して進める。

1. BlenderのOpenXR VRセッションへ入る／終了する
2. HMD正面とテンキーで開始位置・方向を調整する
3. CYCPLUS T2の速度で前進する
4. 実機のハンドル操作で曲がる
5. 操舵の体感を実車と一致させる
6. ステム付近へ計器盤を表示する（Version 0.7.0）
7. 日時と緯度に基づく空を作る（Version 0.8.0）

GoogleタイルはArriettyのVR、走行、操舵から独立した後段プラグインである。Blenderでは1 Blender Unit = 1 m、地面はZ=0、目の高さはZ=1.5 mとする。

## 入力と出力の分担

- HMD表示: Blender OpenXR → SteamVR → HTC VIVE
- HMD正面: Blenderが保持するOpenXR viewer poseをテンキー8/2の位置調整時だけ読む
- 操舵: OpenVRから右コントローラ姿勢を走行中だけ60 Hzで読む。OpenVRクライアントはBlenderプロセス中に再利用する
- 速度・ケイデンス・パワー: CYCPLUS T2のBluetooth FTMS通知をBleakでプッシュ受信する

- IC-KP09: 将来の外部キー入力候補。現在は未実装

T2は通知受信なのでBluetooth値のポーリングをしない。コントローラ姿勢は連続量のため、走行中だけOpenVRで取得し、停止時には読み取りスレッドも終了する。

## 座標と方向

### Blender / HMD

- Blenderは右手系、Z-up、1 unit = 1 m。
- 地面はZ=0、XR base poseの高さは常にZ=1.5 m。
- HMD正面はOpenXR viewer poseのローカル`-Z`軸をBlender XY平面へ投影して使う。
- T2走行の初期方向は保存済みの`arrietty_heading`を使い、HMDの視線から切り離す。
- `arrietty_heading`はBlender XY規約に統一し、0°=+X、90°=+Y、±180°=−X、−90°=−Yとする。
- 走行中のXR base pose位置と角度だけを更新し、Z方向へは移動しない。

### 右コントローラ

- SteamVRはY-up。
- テンキー`0`を押した後、最初の有効姿勢をハンドル中央として記録する。
- 現在姿勢を`R_current`、中央姿勢を`R_center`とし、`R_current @ R_center.T`で取り付け角を除去する。
- SteamVR世界Y軸まわりの相対角を操舵角にする。
- 正が左、負が右。実機テストで符号を確認済み。

## 操作手順

1. SteamVR、HMD、右コントローラを起動する。
2. 右コントローラをステムへ固定し、ハンドルを中央にする。
3. Blenderで`test_data/arrietty_3m_track.blend`を開く。
4. Arriettyパネルの「Dive into Secret World」でVRを開始する。
5. テンキー`4`/`6`でパネルの「Start Direction」をコース方向へ合わせる。
6. T2を数回漕いで起こす。
7. ハンドルを中央に保ったままテンキー`0`を押す。Start Directionが初期進行方向、最初のコントローラ姿勢が操舵角0°になる。
8. T2と右コントローラの両方が受信されると開始音が鳴る。
9. 開始音の後に走行する。距離や周回数では終了せず、テンキー`0`をもう一度押しても停止しない。
10. 走行中にテンキー`7`を押すと飛行モード、もう一度押すと地上モードへ切り替わる。
11. Arriettyパネルの「Back to Real World」でVRから戻る。この時だけ通常の走行停止処理とCSVの終了処理を行う。

小型周回テストシーンは開始位置`(0, -10, 1.5)`、開始方向`+X`、1周約143 m。大型フライト世界は約3.2 km × 2.4 km、開始位置`(0, -320, 1.5)`、開始方向`+X`、1周約2.6 km。どちらも周回数に関係なく走り続ける。

## Version 0.6.5の飛行モード

- テンキー`0`で走行を開始した後、Blenderのキー識別子`NUMPAD_7`（テンキー7）で地上モードと飛行モードを切り替える。
- テンキー`7`は走行開始キーではなく、走行中に飛行／地上を何度でも切り替えるキー。
- T2のFTMS速度を使い、10 km/hまでは高度0 mとする。
- 10 km/hを超えた分について、1 km/hあたり1 m上昇する。
- 高度の式は`max(0, speed_kmh - 10) m`。15 km/hで5 m、20 km/hで10 m。
- XR base poseのZは、地上からの高度にHMD目線の1.5 mを加えた値。
- 地上へ切り替えたとき、走行を終了・中止したとき、エラーが起きたときは高度0 mへ即時に戻す。
- 飛行中も地上と同じ右コントローラ操舵を使う。
- 飛行状態は`flight.py`へ分離し、地上のXY走行計算は変更しない。

2026-08-25の実機ログでは、速度10.95→6.32 km/hに対して目標高度0.95→0.00 mが正しく計算されていた一方、HMDが地上へ戻らなかった。下降式や積分ではなく、開始地点用`base_pose_location`を実行中の連続高度にも使っていたことが原因と判断した。Version 0.6.5ではBlenderのライブXR移動用`XrSessionState.navigation_location.z`へ高度の絶対値を設定する。CSVには実高度、目標高度、XR base／navigation／viewerのZを分けて記録する。

未実装の飛行挙動は、速度変化を滑らかに高度へ反映する処理、滑空、緩やかな着陸、最高高度、地形との衝突である。まず平面上のテストシーンと実機で直接的な速度・高度対応を確認してから追加する。
