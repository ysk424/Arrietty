# Arrietty

Blenderの世界を、好きな大きさで歩くWindows / Godot / OpenXRアプリです。旧Blender拡張を全面的に置き換えました。

**2026-09-15: ユーザーによる実機動作確認済み。** 次回の引き継ぎは [PROJECT_MEMORY.md](docs/PROJECT_MEMORY.md)、継続候補は [ROADMAP.md](docs/ROADMAP.md) を参照してください。

## 起動

```powershell
cd C:\Users\azoo\git\Arrietty
.\start.ps1 "C:\Users\azoo\git\san-marino-vr\san_marino_ground.blend" -h 1.5 -Microphone "USB Microphone"
```

`-h` は足元の地面から目線までの高さ（メートル）。省略時1.5 m、`-h 0.15` で小人、`-h 15` で巨人になります。
このPCではUSB Microphoneで発話から回答まで確認済みです。別のマイクを使う場合は `-Microphone` を変更するか、起動後にYで選びます。
歩行速度、身体の幅、段差を越える高さ、HMDの移動と両眼間隔も基準身長1.5 mに比例します。
入力範囲は0.01〜1000 mですが、極端な大きさはシーンの広さと物理精度に制限されます。

```powershell
# HMDなしで確認
.\start.ps1 "C:\path\world.blend" -h 1.5 -Desktop
# 変換のみ
.\start.ps1 "C:\path\world.blend" -ConvertOnly
# 外部テクスチャなどを変更した場合
.\start.ps1 "C:\path\world.blend" -Rebuild
# 30秒間の描画測定。-Desktopを外すと実機の両眼測定
.\start.ps1 "C:\path\world.blend" -Desktop -BenchmarkSeconds 30
# マイクを明示指定（デバイス名の一意な部分一致も可）
.\start.ps1 "C:\path\world.blend" -Microphone "VIVE Pro"
```

必要なものはPython 3.10以上、Blender、Godot 4.7、OpenXRランタイム（このPCはSteamVR）、Xbox互換コントローラーです。Pythonの追加パッケージは不要です。
SteamVRでHMDを認識させてから起動してください。音声出力はWindowsの既定のスピーカーを使います。
マイクは `-Microphone` または `ARRIETTY_MICROPHONE` で指定できます。省略時はWindowsの既定入力です。HUDで入力先を確認し、Yで切り替えられます。Windows全体の既定デバイスは変更しません。
このPCのローカルビルドのBlenderとGodotを兄弟ディレクトリから自動検出します。
別の配置では `-Blender "…\blender.exe" -Godot "…\godot.exe"`、または環境変数 `ARRIETTY_BLENDER` / `ARRIETTY_GODOT` で指定できます。

## 操作

| Xbox | 操作 |
|---|---|
| 左スティック | 前後左右に歩く。速さはスティック量と身長に比例 |
| 右スティック左右 | 30度ずつ旋回。中央に戻すと次の旋回が可能 |
| View（重なった四角）を1秒長押し | 現在の足元から `-h` の高さに目線を合わせ、今見ている向きを移動の正面にする |
| Xを押して話し、離す | 最大30秒の質問と目線画像を送信 |
| Y | マイクを順に切替。録音・回答待ち中はBで中止してから切替 |
| B | 録音・回答待ち・音声再生を中止 |

立位・座位の切り替え後はView長押しで再調整できます。通常のしゃがみ・頭の上下動は残ります。
初回は追跡が有効になってから自動調整します。
Xboxを再接続してデバイス番号が変わっても、XInput / Xboxを他の仮想入力機器より優先して選び直します。
デスクトップではWASD移動、Q/E旋回、上下矢印で上下を見る、R長押しで再調整、Spaceで話す、Yでマイク切替、Bで中止、Escで終了できます。

## 地面と開始位置

- 衝突用メッシュがあるシーンは、そのデータを優先し、表示メッシュから衝突を追加生成しません。ないシーンではBlenderの表示形状から静的な衝突判定を作ります。平面の床は追加しません。
- 頭の水平移動先を決め、その足元の地面の高さへ同じフレーム内で上下させます。現在の足元を基準に短いレイで坂や階段を追跡し、橋の下で上の道路へ吸着しません。
- 身長1.5 mの歩行速度は1.4 m/s、段差上限25 cm、斜面上限50度。
- 全身のカプセル衝突判定をやめ、頭の移動経路で壁・天井を確認します。脚や胴の近くのスキャン断片で固まらず、しゃがむと頭上の通過判定も変わります。全身の壁への接触は再現しません。
- 現在の `san_marino_ground.blend` の衝突用メッシュは地面16枚だけです。建物の壁・手すりには衝突判定がないため通り抜けられます。壁を止めたい場合は、その壁も衝突用メッシュに含めてください。
- 足場がない端では停止します。飛行や落下は初期仕様に含めていません。
- 開始はアクティブカメラの下の地面と水平方向。カメラが敷地外などの場合は `WalkStart` で始まるEmpty、続いてカメラ周辺を探します。
- `-colonly` を名前に含む衝突用メッシュは非表示でも書き出します。`-col` はGodotの標準規約に従います。
- 見た目だけのメッシュにはBlenderのカスタムプロパティ `arrietty_collision = false` を設定できます。名前に `visual only` を含むメッシュも衝突から除外します。

## 音声と画像

**Whisper (`whisper-1`) → 画像対応GPT → GPT TTS** の順です。
PythonのローカルHTTPサーバーが別スレッドで処理し、Godotは非同期HTTPで待ちます。録音中以外にマイクを起動しません。
質問時だけ、両眼中央の位置・方向から1024×768の画像を1枚描きます。案内には質問、画像、シーン名、目線の座標・方向、直近4往復の会話を渡します。GPTからアプリ内を操作する機能はありません。

`OPENAI_API_KEY` を起動するPowerShellの環境変数に設定してください。このPCでは既存の環境変数を利用できます。
キーをGodot・Blenderや変換ファイルへ渡しません。ローカルサーバーは127.0.0.1のみで受け付け、起動ごとのトークンで保護します。
通常実行では録音・画像・会話をディスクに保存しません。質問を送信するとOpenAI APIが使用されます。

| 環境変数 | 初期値 |
|---|---|
| `ARRIETTY_GPT_MODEL` | `gpt-5.6-luna` |
| `ARRIETTY_TTS_MODEL` | `gpt-4o-mini-tts` |
| `ARRIETTY_TTS_VOICE` | `marin` |

回答はAI合成音声です。観光知識はGPTに任せます。場所や歴史の正確さを保証する専用データベースはありません。
先頭の「ご視聴ありがとうございました」は、認識文と回答文から除去します。表示・会話履歴・読み上げにも除去後の文を使います。その文しか残らない録音は質問として送信しません。
録音中はマイク名と入力レベル（dB）を表示します。無音に近いと約-100 dB、声が入ると数値が上がります。
録音が完全に無音の場合だけAPI送信を止めます。小さい音を一律に除去しません。「無音」「認識が定型文のみ」「認識結果が空」を別々に表示します。
中止しても送信済みのAPI処理は即時停止できない場合があります。次の段階への送信と再生は中止します。
公式API資料: [Whisper](https://developers.openai.com/api/docs/models/whisper-1)、[画像入力](https://developers.openai.com/api/docs/guides/images-vision)、[音声合成](https://developers.openai.com/api/docs/guides/text-to-speech)。

## 描画目標と測定

片眼60 FPSずつは両眼で120枚/秒。両眼1組のフレーム予算は **16.67 ms** です。
90 HzのHMDなら片眼90 FPS、両眼1組 **11.11 ms**。HMDではOpenXRの更新周期に従い、60 FPSに固定しません。
通常のデスクトップは60 FPS、デスクトップの測定モードは上限なしです。

Mobileレンダラー/Vulkan、MSAA 4x。ポリゴン削減・自動LOD生成・解像度の自動低下は行いません。
HUDにFPSとメインViewportのGPU時間を表示し、終了時にキャッシュ内の `metrics.json` に1秒ごとの値を保存します。
GPU値はエンジンの描画計測で、HMDコンポジターの再投影や転送時間は含みません。デスクトップの測定だけで両眼の目標達成を判断しないでください。

## 変換と制限

元の `.blend` は保存せず、別Blenderプロセスで現在のシーンを静的GLBへ変換します。
シーン単位をメートルに換算し、形状、対応するマテリアル・テクスチャ・頂点色を持ち込みます。
照明にはglTFのCOMPATモードを使います。任意のBlenderシェーダー、ボリューム、シミュレーション、アニメーションの再現には別途ベイクなどが必要です。見た目の完全な一致は保証しません。

キャッシュは `.cache/<fingerprint>/` に置きます。元ファイル内容、変換スクリプト、Blender実行ファイルの更新でキャッシュが変わります。
外部参照ファイルだけの変更には `-Rebuild` を使ってください。同じシーンの複数同時起動は想定していません。
`convert.log` / `import.log` / `runtime.log` にエラーを記録します。
`diagnostics.json` には1秒ごとにコントローラーの認識・ボタン・スティック、HMD追跡状態、FPS、歩行の停止理由と処理時間、選択マイクと録音時間・音量・処理段階を上書き保存します。会話本文と録音は保存しません。

## 検証

```powershell
python tools/verify.py
# 明示的に実行する有料API統合テスト。合成音声を使用し、マイク録音なし
python tools/verify_voice_live.py ".cache\変換済みプロジェクトのID"
# サンマリノの停止地点で上り下りを再現（変換済みキャッシュに対して実行）
..\godot\bin\godot.windows.editor.x86_64.exe --headless --xr-mode off --path ".cache\変換済みプロジェクトのID" --script res://tests/street_regression.gd
```

2026-09-15、このPCでローカルビルドGodot 4.7.2 / Blender 5.2.2を使い確認:

- サンマリノの27表示メッシュ、716,024三角形の変換・描画。
- 身長15 cm・1.5 m・15 mの階段、斜面、上下に重なる床、端、壁、座位の高さと正面の再調整、しゃがみ。
- 身体の物理的な移動による坂への追従、移動の二重適用防止、階段の頭上判定、重なる三角形の地面、胴の高さのスキャン断片での前後移動を含む34項目のGodotテスト。
- 実際のサンマリノで停止した座標から、上り2.8 m・下り2.8 m、標高差約20 cmを往復。地面16枚の衝突メッシュを使用。
- センチメートル単位の変換、カメラ位置、非表示の衝突メッシュ。
- 音声の順序、画像・会話の引き渡し、入力検証、認証、処理中のキャンセル。
- 合成した試験音を録音バスへ流し、録音データ・入力メーター・無音のモニター出力を含む13項目を確認。
- 実機のUSB Microphoneで、約3.64秒の発話を認識し回答完了。録音ピーク約-14.1 dB、RMS約-29.6 dB、無音判定なし。
- 実APIで、合成した日本語の質問 → Whisper → 実際の目線画像とGPT → 音声生成 → Godotの音声読み込みまで通過。

HMDでの表示と、ユーザーによる90 FPS / GPU約0.8 msの表示を確認しました。これはその時点の視点での値です。
HMDトラッカー名の誤りでXbox入力処理まで進まない不具合と、Xbox再接続時の機器選択を修正し、HMDとXboxを併用する入力経路の16項目の回帰テストを追加しました。新しい地面追従方式、Xbox操作、音声機能を含む最終状態について、ユーザーから「ちゃんと動いた。ここまでOK」と確認を受けました。
